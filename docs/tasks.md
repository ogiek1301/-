# 実装タスク一覧

作成日: 2026-09-07
バージョン: 0.1
対応する技術設計書: `docs/design.md` バージョン 0.2

## この文書の読み方

- 各タスクは1〜2時間で完了できる粒度に分割している。1タスクが2時間を超えそうな場合は、着手前にタスクを分割し直す
- 上から下へ、依存関係の順に並んでいる。後のタスクは前のタスクの成果物を前提とする。並び替えて進めない
- 各タスクの完了条件（Definition of Done）には、コードレベルの条件（型チェック・lint）と、**ブラウザで実際に確認できる条件**の両方を含める。後者を満たさずに完了として報告しない（`AGENTS.md` の「やってはいけないこと」参照）
- チェックボックスは実装が完了した時点でチェックする。着手前に「実装済み」と書かれているタスクは、前回のセッションまでに完了しているものである

## MVP と後回しの区分

要件定義書 4.1 の3画面・4ルートが動作し、要件 5章の F-01〜F-08、F-11〜F-14 が一通り触れる状態を MVP とする。次の2グループは MVP から後回しにする。

- **音声入力（F-09）とルールベース日付推測（F-10）**: 要件 9章の未決事項 O-11（実機が Android か iOS か）と O-13（音声入力の外部通信を許容するか）が未決のままであり、実装しても使えるかどうかが確定しない。MVP はテキスト入力のみで完結させ、この2機能は決定後に追加する
- **性能検証・自動テスト**: 要件 6.5 の1000件基準の実測や、O-14（自動テスト導入）は未決のため、MVP には含めない

「後回し」と明記していないタスクはすべて MVP に含む。

`src/components/ui/`（`Button.tsx`、`Checkbox.tsx`、`TextField.tsx`）は Tailwind の組み合わせをまとめた薄いラッパーであり、単体で確認できる画面を持たないため、このリストでは独立したタスクにしていない。すでに実装済みで、後続のフェーズ（1〜5）で他のコンポーネントから呼び出された時点でブラウザ上の確認対象に含まれる。

  - 内容: 1000件のタスクを注入し、チェックボックスのタップ応答とタブ切り替えの再描画時間をブラウザ内計測（`performance.now()` + `MutationObserver`）で測定した

  - 対応方針をユーザーに確認した結果、「1人用アプリであり実際の未完了タスクは日常的に数十件程度に留まる見込み（完了タスクは翌日に自動アーカイブされ一覧の描画対象から外れる）ため、今は対応不要」との判断になった。この結果と判断は要件定義書 9章の O-12 に記録した。1000件規模の性能はコードでは未対応のまま据え置く
