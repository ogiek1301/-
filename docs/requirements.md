## 1. 概要・目的

スマートフォンで使う、1人用のタスク管理アプリケーションを作る。

このアプリが解決する課題は次の3点である。

1. やるべきタスクが頭の中や複数の場所に散らばっていて、全体像を把握できない
2. 「今日やること」と「中長期の期日があるもの」を、同じ場所で見られない
3. 思いついたタスクを入力する手間が大きく、記録が続かない

これに対し、本アプリは次の方針をとる。

- タスクと予定（人との約束）を**単一のデータ型**として扱い、1つの一覧で管理する。予定は「時刻の指定があるタスク」として表現する
- 期日を持つタスクを月表示カレンダー上に配置し、日単位・時間単位の見通しを与える
- 音声入力とルールベースの日付推測により、入力の手間を減らす
- 外部カレンダーへの登録は、Gemini に貼り付けるためのプロンプト文を生成することで補助する

データはブラウザの localStorage にのみ保存する。アプリケーション用のサーバー、データベース、外部 API を使用しない。ただし音声入力機能に限り、ブラウザ内蔵の仕組みを経由して外部への通信が発生する（詳細は 6.7 に記載）。

## 4. 画面一覧

### 4.1 画面数の定義

本書における「画面」とは、画面下部の固定ナビゲーションから到達できる主要画面を指す。次のものは画面数に含めない。

- 追加と編集のように、同一のフォームコンポーネントを共有するルート
- モーダル、確認ダイアログ、トースト
- 画面内のタブによる表示切り替え

この定義により、主要画面は3つ、ルートは4つとなる。

### 4.2 画面一覧

| 画面ID | 画面名 | URL | 役割 |
| --- | --- | --- | --- |
| S-01 | タスク一覧 | `/` | タスクの表示、完了操作、削除操作、Gemini プロンプト生成の起点 |
| S-02 | カレンダー | `/calendar` | 期日を持つタスクを月表示カレンダー上に配置して表示する。日付を選択するとその日のタスクを表示する |
| S-03 | タスク追加・編集 | `/tasks/new`（追加）<br>`/tasks/[id]`（編集） | タスクの各項目を入力・変更する。音声入力とルールベースの日付推測を提供する |

S-01 を起動時の初期表示とする。

S-01 は「今日 / 全体」と「未完了 / アーカイブ / ごみ箱」の2軸の切り替えを持つ。加えて F-07 のカテゴリ絞り込みがあり、375px 幅に3軸の操作要素を配置する必要がある。この配置は未決事項 O-01 とする。

## 5. 機能要件

### 5.1 データモデル

#### 5.1.1 保存形式

localStorage には次の構造で単一のキーに保存する。

```
キー: "task-app-data"
値:   { "schemaVersion": 1, "tasks": Task[] }
```

`schemaVersion` はスキーマ変更時のマイグレーション判定に使用する（F-14）。

#### 5.1.2 Task 型

タスクは次のフィールドを持つ。予定（人との約束）も同じ型で表現し、`startTime` に値が入っているものを予定として扱う。

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string | 必須 | 一意の識別子。生成方法は 6.8 に従う |
| `title` | string | 必須 | タスク名。前後の空白を除去した後に1文字以上100文字以下 |
| `memo` | string | 任意 | 詳細説明。0文字以上1000文字以下 |
| `dueDate` | string \| null | 任意 | 期日。`YYYY-MM-DD` 形式の日本時間の日付 |
| `startTime` | string \| null | 任意 | 開始時刻。`HH:mm` 形式。値がある場合は予定として扱う |
| `endTime` | string \| null | 任意 | 終了時刻。`HH:mm` 形式 |
| `priority` | `"high"` \| `"medium"` \| `"low"` | 必須 | 優先度 |
| `category` | string \| null | 任意 | カテゴリ名。1文字以上20文字以下。自由入力とする |
| `status` | `"active"` \| `"archived"` \| `"trashed"` | 必須 | 状態 |
| `completedAt` | string \| null | 任意 | 完了日時。ISO 8601 形式 |
| `archivedAt` | string \| null | 任意 | アーカイブへ移動した日時。ISO 8601 形式 |
| `trashedAt` | string \| null | 任意 | ごみ箱へ移動した日時。ISO 8601 形式 |
| `createdAt` | string | 必須 | 作成日時。ISO 8601 形式 |
| `updatedAt` | string | 必須 | 更新日時。ISO 8601 形式 |

#### 5.1.3 状態の定義

`status` と `completedAt` の組み合わせにより、タスクは次の4つの状態のいずれか1つをとる。本書で「未完了タスク」と書いた場合、必ず下表の定義を指す。

| 状態名 | 条件 | S-01 での表示先 |
| --- | --- | --- |
| 未完了タスク | `status === "active"` かつ `completedAt === null` | 「未完了」タブ |
| 完了済みタスク | `status === "active"` かつ `completedAt !== null` | 「未完了」タブの末尾 |
| アーカイブ | `status === "archived"` | 「アーカイブ」タブ |
| ごみ箱 | `status === "trashed"` | 「ごみ箱」タブ |

#### 5.1.4 日付の扱い

すべての日付は日本時間（Asia/Tokyo）のローカル日付として扱う。

- 「本日」の判定は、現在時刻を Asia/Tokyo で `YYYY-MM-DD` 形式の文字列に変換し、`dueDate` と文字列比較して行う
- `new Date("2026-09-07")` のように**日付のみの文字列**を `Date` に渡す実装は禁止する。この形式は UTC として解釈され、日本時間では1日ずれるため
- 日付の前後比較は、`YYYY-MM-DD` 形式の文字列比較で行う

上記の禁止は日付のみの文字列に対するものである。**タイムゾーン指定を含む ISO 8601 日時文字列（末尾が `Z` のもの）のパースは禁止の対象外**とする。この形式は絶対時刻を一意に表すため、解釈のずれが生じない。

`completedAt` から日本時間の日付を取り出す処理（F-04 の自動アーカイブ判定、F-06 の今日ビュー）では、次の変換関数を使用する。この関数以外の場所で日付への変換処理を書いてはならない。

```typescript
// UTC の ISO 8601 日時文字列を、日本時間の YYYY-MM-DD に変換する。
// ロケール "sv-SE" は YYYY-MM-DD 形式を返すため、文字列の組み立てが不要になる。
export function toJstDate(isoDateTime: string): string {
  return new Intl.DateTimeFormat("sv-SE", {
    timeZone: "Asia/Tokyo",
  }).format(new Date(isoDateTime));
}

// 現在時刻の日本時間の日付を YYYY-MM-DD で返す。
export function todayJst(): string {
  return toJstDate(new Date().toISOString());
}
```

この方式を採ることで、日付比較はすべて `YYYY-MM-DD` の文字列比較で完結する。`completedAt` とは別に日付フィールドを持たせる必要はない。

### 5.2 F-01 タスクの作成

タスク追加画面を開いたとき、優先度は「中」（`"medium"`）が選択された状態にする。3段階の中央であり、利用者が判断を保留したまま保存できるためである。

```
Given 利用者がタスク追加画面 (/tasks/new) を開いた
When  優先度を変更せずにタイトルだけを入力して保存ボタンを押す
Then  priority="medium" のタスクが保存される
```

```
Given 利用者がタスク追加画面 (/tasks/new) を開いている
When  タイトルに「資料を作る」と入力し、優先度「高」を選択し、保存ボタンを押す
Then  タスクが status="active"、completedAt=null として localStorage に保存され、
      画面がタスク一覧 (/) に遷移し、保存したタスクが「未完了」タブに表示される
```

```
Given 利用者がタスク追加画面を開いている
When  タイトルを空のまま保存ボタンを押す
Then  タスクは保存されず、タイトル入力欄の下に「タイトルを入力してください」と表示される
```

```
Given 利用者がタスク追加画面を開いている
When  タイトルに半角スペース3文字だけを入力して保存ボタンを押す
Then  タスクは保存されず、「タイトルを入力してください」と表示される
```

```
Given 利用者がタスク追加画面を開いている
When  タイトルに101文字を入力して保存ボタンを押す
Then  タスクは保存されず、「タイトルは100文字以内で入力してください」と表示される
```

```
Given 利用者がタスク追加画面を開いている
When  メモに1001文字を入力して保存ボタンを押す
Then  タスクは保存されず、「メモは1000文字以内で入力してください」と表示される
```

```
Given 利用者がタスク追加画面を開いている
When  期日を空のまま開始時刻「19:00」を入力して保存ボタンを押す
Then  タスクは保存されず、「時刻を入力する場合は期日も入力してください」と表示される
```

```
Given 利用者がタスク追加画面を開いている
When  開始時刻「21:00」と終了時刻「19:00」を入力して保存ボタンを押す
Then  タスクは保存されず、「終了時刻は開始時刻より後にしてください」と表示される
```

```
Given 利用者がタスク追加画面を開いている
When  タイトルと期日「2026-09-10」と開始時刻「19:00」と終了時刻「21:00」を入力して保存ボタンを押す
Then  タスクが保存され、カレンダー画面の9月10日に「19:00-21:00」付きで表示される
```

### 5.3 F-02 タスクの編集

```
Given タスク一覧に「資料を作る」というタスクが表示されている
When  そのタスクをタップする
Then  タスク編集画面 (/tasks/[id]) に遷移し、全フィールドに保存済みの値が入った状態で表示される
```

```
Given 利用者がタスク編集画面で優先度を「高」から「低」に変更した
When  保存ボタンを押す
Then  localStorage 上の該当タスクの priority が "low" に更新され、updatedAt が現在時刻に更新され、
      画面がタスク一覧に遷移する
```

```
Given 存在しない id を含む URL (/tasks/xxxx) を開いた
When  画面を表示する
Then  「タスクが見つかりません」という文言と、タスク一覧へ戻るボタンが表示される
```

### 5.4 F-03 タスクの完了

```
Given タスクが3件登録された状態で、利用者がタスク一覧 (/) を開いている
When  1件目のチェックボックスをタップする
Then  そのタスクの completedAt に現在時刻が記録され、
      その行のタイトルに取り消し線が表示され、その行が一覧の末尾に移動する
```

```
Given 1件目のタスクを完了状態にした
When  ページをリロードする
Then  1件目のタスクの取り消し線が表示されたままになり、完了状態が保持される
```

```
Given 完了状態にしたタスクが一覧に表示されている
When  同じチェックボックスをもう一度タップする
Then  completedAt が null に戻り、取り消し線が消え、期日と優先度に応じた並び順の位置に戻る
```

### 5.5 F-04 完了タスクの自動アーカイブ

自動アーカイブの基準は日付境界とする。完了した日の翌日0時（日本時間）を過ぎたタスクをアーカイブする。

```
Given 昨日以前に completedAt が設定された完了済みタスクが存在する
When  利用者がアプリを開く
Then  そのタスクの status が "archived" に変更され、archivedAt に現在時刻が記録され、
      「未完了」タブから消え、「アーカイブ」タブに移動する
```

```
Given 本日 completedAt が設定された完了済みタスクが存在する
When  利用者がアプリを開く
Then  そのタスクは status="active" のまま「未完了」タブの末尾に残る
```

```
Given アーカイブタブにタスクが存在する
When  利用者がそのタスクの「戻す」ボタンを押す
Then  status が "active" に戻り、completedAt と archivedAt が null になり、
      「未完了」タブに再度現れる
```

### 5.6 F-05 タスクの削除（ごみ箱への移動）

```
Given タスク一覧にタスクが表示されている
When  利用者がそのタスクの削除ボタンを押す
Then  status が "trashed" に変更され、trashedAt に現在時刻が記録され、
      「未完了」タブから消え、「ごみ箱」タブに移動する。
      localStorage からデータは消えない
```

```
Given ごみ箱タブにタスクが存在する
When  利用者がそのタスクの「復元」ボタンを押す
Then  status が "active" に戻り、trashedAt が null になり、「未完了」タブに再度現れる
```

```
Given ごみ箱タブにタスクが存在する
When  利用者が「完全に削除」ボタンを押す
Then  確認ダイアログが表示され、「削除する」を選んだ場合のみ localStorage から該当データが消える
```

### 5.7 F-06 タスク一覧の表示と並び替え

並び順は次の規則で決定する。

1. 未完了タスクを先に、完了済みタスクを後に配置する
2. 未完了タスクどうしは、期日の昇順に並べる
3. 期日が同じ場合は、優先度の高い順（高 → 中 → 低）に並べる
4. 期日が同じかつ優先度が同じ場合は、開始時刻の昇順に並べる。開始時刻を持たないタスクは後ろに置く
5. 期日を持たないタスクは、期日を持つタスクすべての後ろに置く
6. 完了済みタスクどうしは、completedAt の降順に並べる

アーカイブタブとごみ箱タブの並び順は次のとおりとする。

- アーカイブタブは `archivedAt` の降順（新しくアーカイブされたものが上）に並べる
- ごみ箱タブは `trashedAt` の降順（新しく削除されたものが上）に並べる
- どちらのタブも件数の上限を設けず、全件を表示する

```
Given アーカイブタブに3件のタスクが存在する
When  利用者がアーカイブタブを開く
Then  archivedAt の降順に並んだ状態で全件が表示される
```

```
Given ごみ箱タブに3件のタスクが存在する
When  利用者がごみ箱タブを開く
Then  trashedAt の降順に並んだ状態で全件が表示される
```

```
Given 未完了タスクと完了済みタスクが混在している
When  利用者がタスク一覧 (/) の「未完了」タブを開く
Then  上記1から6の規則に従って並んだ状態で表示される
```

```
Given タスク一覧が表示されている
When  利用者が「今日」タブを選択する
Then  次の2種類のタスクのみが表示される。
      (a) 未完了タスクのうち、dueDate が本日または本日より前のもの
      (b) 完了済みタスクのうち、completedAt が本日のもの
```

```
Given タスク一覧が表示されている
When  利用者が「全体」タブを選択する
Then  未完了タスクと完了済みタスクがすべて表示される
```

```
Given 未完了タスクが1件も存在しない
When  利用者がタスク一覧を開く
Then  「タスクがありません」という文言と、タスク追加画面へのボタンが表示される
```

### 5.8 F-07 カテゴリによる絞り込み

カテゴリは自由入力とする。あらかじめ定めた選択肢は持たない。選択肢の一覧は、保存済みタスクの `category` から重複を除いて算出する。カテゴリ専用の保存領域は設けない。

```
Given カテゴリ「仕事」が設定されたタスクと、カテゴリ「私用」が設定されたタスクが存在する
When  利用者がカテゴリ「仕事」を選択する
Then  category="仕事" のタスクのみが一覧に表示される
```

```
Given 過去に「仕事」「私用」の2つのカテゴリを使用したタスクが存在する
When  利用者がタスク追加画面でカテゴリ入力欄をタップする
Then  「仕事」「私用」が入力候補として表示され、タップで入力できる。
      候補にない文字列を直接入力することもできる
```

```
Given カテゴリ「仕事」を持つタスクがすべて削除され、ごみ箱に移動した
When  利用者がタスク一覧のカテゴリ絞り込みを開く
Then  「仕事」は選択肢に表示されない
```

### 5.9 F-08 カレンダー表示


## 6. 非機能要件

### 6.1 対応環境

音声入力（F-09）が動作するのは Android Chrome とデスクトップ版の Chrome / Edge に限られる。iOS 上のブラウザはすべて WebKit で動作するため、音声入力は利用できない。

| 区分 | ブラウザ | 音声入力 | それ以外の機能 |
| --- | --- | --- | --- |
| 主対象 | Android Chrome | 動作する | 動作する |
| 動作確認対象 | デスクトップ Chrome、Edge | 動作する | 動作する |
| 制限付き対応 | iOS Safari、iOS Chrome | 動作しない。F-09 の代替文言を表示する | 動作する |

| 項目 | 内容 |
| --- | --- |
| 優先端末 | スマートフォン。モバイルファーストで設計する |
| PC 対応 | レイアウトが崩れない範囲までとする。PC 向けの専用レイアウトは作らない |
| 画面幅の基準 | 375px を基準に設計し、768px 以上では最大幅を制限して中央寄せにする |

利用者の実機が iOS の場合、音声入力は本アプリの機能として成立しない。実機は未確定のため（O-11、解決済み）、iOS でも安全に動作するよう F-09 は対応判定による代替表示を持つ。

### 6.2 データ量

| 項目 | 内容 |
| --- | --- |
| 想定件数 | 数千件 |
| 保存上限 | localStorage の約5MB。日本語を含む場合の実効容量は約2.5MB と見積もる |
| 対策 | 完了した日の翌日0時を過ぎたタスクを自動でアーカイブし、「未完了」タブの描画対象から外す |

### 6.3 データの永続性と消失リスク

- データは利用者の端末のブラウザの localStorage にのみ保存する
- 端末間、ブラウザ間でデータは共有されない
- エクスポート機能、インポート機能は作らない。したがってデータが失われた場合の復旧手段は存在しない

データが利用者の操作なしに失われる条件が存在する。

| 条件 | 内容 |
| --- | --- |
| iOS の ITP | iOS Safari および iOS 上のブラウザでは、7日間サイトを訪問しないと localStorage が自動削除される |
| プライベートブラウジング | プライベートモードで開いた場合、タブを閉じた時点でデータが消える |
| ストレージ逼迫 | 端末の空き容量が不足した場合、ブラウザがデータを破棄することがある |
| ブラウザのデータ削除 | 利用者がブラウザの閲覧データ削除を実行した場合 |

毎日利用するという前提のもとでは ITP の7日間条件は発動しないが、この前提が崩れた場合にデータが失われる点を利用者は了解している。

### 6.4 バリデーション

| 対象 | ルール | 違反時の動作 |
| --- | --- | --- |
| タイトル | 前後の空白を除去した後に1文字以上100文字以下 | 保存を中止し、入力欄の下にエラー文言を表示する |
| メモ | 1000文字以下 | 保存を中止し、入力欄の下にエラー文言を表示する |
| カテゴリ | 前後の空白を除去した後に1文字以上20文字以下。未入力の場合は null を保存する | 保存を中止し、入力欄の下にエラー文言を表示する |
| 開始時刻・終了時刻 | 入力する場合は期日が入力されていること | 保存を中止し、エラー文言を表示する |
| 終了時刻 | 開始時刻より後であること | 保存を中止し、エラー文言を表示する |
| 期日の日付 | 妥当性のチェックは行わない。過去日付の警告も行わない | — |

文字数は `Array.from(str).length` により、Unicode のコードポイント単位で数える。`String.prototype.length` は使用しない。後者は UTF-16 のコード単位を数えるため、絵文字や一部の漢字が2文字として数えられ、利用者の見た目と一致しないためである。

### 6.5 パフォーマンス

保存方式は 5.1.1 のとおり単一キーへの全件書き込みとする。1件の更新のたびに全件を直列化するため、書き込みは500ミリ秒のデバウンスをかけ、連続操作時の書き込み回数を抑える。

検証可能な基準を次のとおり定める。

| 項目 | 基準 |
| --- | --- |
| チェックボックスの応答 | タスク1000件を保持した状態で、タップから取り消し線が表示されるまで200ミリ秒以内 |
| 画面遷移 | タスク1000件を保持した状態で、タブ切り替えから一覧の再描画完了まで200ミリ秒以内 |
| 初期表示 | localStorage の読み込み中はスケルトンを表示し、内容のない白画面を表示しない |

1000件規模での実測ではこの基準を満たせなかったが、O-12 のとおり実際の未完了タスク件数が少ないと見込まれることから、現時点では保存キーの分割・再描画の最適化のいずれも行わないと決定した。

### 6.6 データの誤削除への対応

- 一覧からの削除操作では、データを完全に削除せず `status="trashed"` に変更する
- ごみ箱からの復元を可能にする
- ごみ箱からの完全削除と、F-13 のデータ初期化の2つの操作のみ、確認ダイアログを表示する
- ごみ箱を自動的に空にする処理は行わない。ごみ箱に入れたタスクは、利用者が完全削除を実行するまで保持し続ける。1人用アプリであり、ごみ箱に溜まる件数が容量上限に影響する規模にならないためである
- ごみ箱とアーカイブへの移動日時は `trashedAt` と `archivedAt` に記録する。これは各タブの並び順に使用する

### 6.7 通信

| 機能 | 通信の有無 |
| --- | --- |
| ページの配信 | 発生する |
| 音声入力（F-09） | **発生する。** ブラウザが音声データを外部の音声認識サーバーへ送信する。オフラインでは動作しない |
| 上記以外のすべての機能 | 発生しない。アプリケーションから外部 API を呼び出す実装は行わない |

音声入力の通信はブラウザの内蔵実装によるものであり、本アプリが送信先を選択したり制御したりすることはできない。この通信を許容するかどうかは O-13 で許容すると決定した。

### 6.8 実行環境の制約（セキュアコンテキスト）

`navigator.clipboard` と `crypto.randomUUID()` は、HTTPS または localhost でのみ利用できる。開発中にスマートフォン実機から `http://192.168.x.x:3000` の形式で接続した場合、これらは利用できない。F-11 と F-12 のコピー機能は本アプリの中核であるため、次の対応を必須とする。

| 対象 | 対応 |
| --- | --- |
| クリップボードへのコピー | `navigator.clipboard` が利用できない場合、プロンプト文を全選択状態のテキストエリアに表示し、利用者が長押しでコピーできる状態にする。「コピーしました」の代わりに「長押しでコピーしてください」と表示する |
| ID の生成 | `crypto.randomUUID()` を使用しない。現在時刻のミリ秒値と `Math.random()` を組み合わせた文字列で生成する |

### 6.9 検証方法

- 本書のすべての受け入れ条件は、6.1 の主対象ブラウザで手動により検証する
- 自動テストの導入可否は未決事項 O-14 とする
- エラー発生時は `console.error` に出力する。外部へのエラー送信は行わない

### 6.10 その他

| 項目 | 内容 |
| --- | --- |
| 認証 | 行わない |
| 対応言語 | 日本語のみ |
| アクセシビリティ | チェックボックスとボタンに `aria-label` を設定する。それ以外の対応は本バージョンでは行わない |
| 画面の状態の保存 | タブの選択状態とカテゴリ絞り込みの状態は保存しない。アプリを開くたびに「今日」タブ、「未完了」タブ、カテゴリ絞り込みなしの状態で表示する |

| データベース、アプリケーションサーバーの保存 | 前提条件により使用しない |
| 端末間・ブラウザ間のデータ同期 | サーバーなしでは実現不可能なため |

| Gemini の出力をアプリに取り込む機能 | 利用者の判断により、手動入力とすることにしたため |
| 音声認識テキストの意味的な整形・要約 | 外部 API なしでは実現不可能なため。8語のキーワードによる日付推測のみ行う |

| メールの送信 | 送信にはサーバーが必要となるため |
| 通知、リマインダー、プッシュ通知 | 本バージョンの対象外 |
| 繰り返しタスク、定期タスク | 本バージョンの対象外 |
| タスクの検索、全文検索 | 本バージョンの対象外 |
| サブタスク、タスクの階層構造 | 本バージョンの対象外 |
| 複数日にまたがる予定 | 本バージョンの対象外。予定は1日の中で完結するものとする |
| 添付ファイル、画像の登録 | localStorage の容量制約のため |
| ダークモードの切り替え | 本バージョンの対象外 |
| オフライン動作の保証（Service Worker） | 本バージョンの対象外 |
| 自動テスト | 未決事項 O-14 の決定まで保留 |

## 8. 用語集

| 用語 | 定義 |
| --- | --- |
| タスク | 本アプリが管理するデータの単位。やるべきことと、人との約束の両方を含む |
| 予定 | `startTime` に値が設定されているタスクを指す呼び方。データ型としてはタスクと同一であり、別のデータ型は存在しない |
| 優先度 | タスクの重要度。「高」「中」「低」の3段階 |
| 期日 (`dueDate`) | タスクを終わらせる日付。`YYYY-MM-DD` 形式の日本時間の日付 |
| 開始時刻 (`startTime`) | 予定が始まる時刻。`HH:mm` 形式 |
| 終了時刻 (`endTime`) | 予定が終わる時刻。`HH:mm` 形式 |
| カテゴリ | タスクを分類するための文字列。1つのタスクに0個または1個 |
| 未完了タスク | `status === "active"` かつ `completedAt === null` のタスク |
| 完了済みタスク | `status === "active"` かつ `completedAt !== null` のタスク。「未完了」タブの末尾に表示される |
| アーカイブ (`archived`) | 完了した日の翌日0時を過ぎ、「未完了」タブから自動的に外された状態 |
| ごみ箱 (`trashed`) | 利用者が削除操作を行い、「未完了」タブから外された状態。復元できる |
| 完全削除 | ごみ箱の中のタスクを localStorage から消す操作。復元できない |
| 今日ビュー | タスク一覧の「今日」タブ。期日が本日以前の未完了タスクと、本日完了した完了済みタスクを表示する |
| Gemini プロンプト | 利用者が Gemini に貼り付けるために、アプリが生成する文章。アプリから Gemini への送信は行わない |
| カレンダー登録用プロンプト | 未完了タスクを外部カレンダーに登録させるための Gemini プロンプト |
| 整理用プロンプト | 貼り付けた未整理テキストをタスクの形に整理させるための Gemini プロンプト |
| localStorage | ブラウザがドメインごとに持つ保存領域。容量上限は約5MB |
| Web Speech API | ブラウザに内蔵された音声認識の仕組み。認識処理は端末内で完結せず、外部サーバーへの通信を伴う |
| セキュアコンテキスト | HTTPS または localhost で配信されている状態。一部のブラウザ API がこの条件を要求する |
| ITP | iOS の WebKit が持つ追跡防止機能。7日間未訪問のサイトの localStorage を自動削除する |
| `schemaVersion` | 保存データの構造のバージョン番号。マイグレーション判定に使用する |

### 解決済みの項目

| ID | 項目 | 決定内容 |
| --- | --- | --- |
| O-11 | 実機端末の確定 | 未確定。両方の端末で使う可能性があるため、機種を前提にした実装はしない。音声入力（F-09）は `webkitSpeechRecognition` の対応判定により、Android では動作し、iOS を含む非対応ブラウザでは自動的に代替文言を表示する実装とした（F-09、F-10、6.1、6.3） |
| O-13 | 音声入力の外部通信を許容するか | 許容する。F-09 を実装する（6.7、US-03） |
| O-07 | 月表示カレンダーでの時刻の見せ方 | 件数のみを出し、日付タップ時に時刻を見せる方式とする。既存の `MonthCalendar`（件数表示）と `DayTaskList`（タップ時に時刻表示）の実装がこの方式そのものだったため、追加の実装は不要だった（F-08） |
| O-08 | 期限切れタスクの見せ方 | 一覧上で色により区別する。期日が本日より前の未完了タスクは、期日の文字を赤字にする（F-06） |
| O-12 | 保存キーの分割 | 分割しない。1000件規模ではチェックボックスのタップ応答・タブ切り替えの再描画とも200ミリ秒の基準を実測で超えた（約460〜650ms）が、1人用アプリであり実際の未完了タスクは日常的に数十件程度に留まる見込み（完了タスクは翌日に自動アーカイブされ一覧の描画対象から外れるため）であることから、現時点では保存キー分割・再描画の最適化ともに対応しないと判断した。件数が実際に問題になった場合に改めて検討する（5.1.1、6.5） |
| O-04 | 自動アーカイブの基準 | 経過時間ではなく日付境界とし、完了した日の翌日0時を過ぎたタスクをアーカイブする（F-04） |
| O-05 | 優先度の初期値 | 「中」（`"medium"`）とする。3段階の中央であり、判断を保留したまま保存できるため（F-01） |
| O-06 | カテゴリの入力方式 | 自由入力とする。選択肢は保存済みタスクの category から重複を除いて算出し、入力候補として表示する。カテゴリ専用の保存領域は設けない。文字数は20文字以下（F-07、6.4） |
| O-09 | ごみ箱の保持期間 | 自動削除は行わない。利用者が完全削除を実行するまで保持する（6.6） |
| O-10 | 容量上限に近づいた場合の挙動 | F-13 に受け入れ条件として追加した |
